Actual particle trails and laser fields surround physical engineering artifacts. Warm, wide HTML identity holds the composition while gold and cyan diffraction move across a dark foil card. **Key Characteristics:**

- Full-scale official particle and laser fields behind readable HTML.

## Colors

Warm identity and contact gold sit inside optical black and blue-black glass; cyan carries interaction and instrument signals.

### Primary

- **Routed Cyan** (signal): shared links, keyboard focus, active paths and instrument states.

### Secondary

- **Contact Gold** (gold): the home name's dot, physical contacts and the foil/material vocabulary. Warm gold highlights identify the selected home system.

### Tertiary

- **Fault Red** (fault): demonstrated fault, tamper or missing-data states in functional instruments.

### Neutral

- **Optical Black** (bg): page ground and decorative field hosts.
- **Dark Glass** (surface) and **Raised Glass** (surface-high): technical layers and reading surfaces.
- **Warm Identity** (text): primary HTML text and emphasized prose.
- **Technical Mist** (muted): supporting prose and technical labels.
- **Machined Divider** (line): structural separators.

Shader colors, light colors and translucent DOM gradients are material treatments, not additional semantic status colors. Their source values are recorded in docs/DESIGN-IMPLEMENTATION.md. Sidecar tonal ramps are synthesized panel previews, not application tokens.

**The Signal Meaning Rule.** Cyan marks interaction or signal; fault red belongs to a demonstrated failure state, and gold carries material warmth and selected home-system emphasis.

**The HTML Identity Rule.** Names, headings, control labels and project truth stay in HTML; rendered card printing supplements them.

## Components

### Buttons

The main project action adapts the exact original ThreeUI Ignition vertex and fragment shaders into a native portfolio link. Its HTML label and arrow remain readable without WebGL. Hover/focus drives shader response; click triggers the local flash while following the link. The shell lifts (2px) on hover and presses (1px) on activation; reduced motion removes the lift transition and fixes shader time.

Secondary project actions use a cool reflective pill. Text actions retain a (44px) minimum target. Shared links, buttons and inputs use a (2px) cyan focus outline with a (5px) offset; the card canvas uses a (2px) cyan inset outline with a (-10px) offset. Disabled controls reduce opacity.

### Navigation

Desktop navigation uses a translucent pill rail, small technical labels and a selected fill. On the home route its ground is more transparent and its outer shadow is removed. Mobile uses a circular menu button and a rounded menu panel. Reduced transparency replaces backdrop blur with an opaque dark surface.

### Cards / Containers

The owner selected the first generated avatar on 9 October 2026. The hero now pairs the personal typography with that standalone gold/cyan portrait, without a card frame. It is a raster illustration based on the supplied owner photograph; no project names, telemetry or fixture data appear in the hero. Its lower edge fades into the existing atmosphere. Desktop aligns the portrait and name from the same top edge; the image's transparent head margin is compensated in CSS. A presentation mirror makes the avatar face inward toward the name, preserving the original asset. Compact screens place the portrait below the identity and action. Flow Field is subdued behind the content.

HomeMotionProvider controls Ignition, avatar pointer response and every home field, including later mounts. A native Pause/Resume control and Replay Entry remain available. Fine-pointer movement translates the portrait by at most six horizontal/four vertical pixels and shifts a restrained local light. Motion values avoid per-pointer React rerenders; offscreen, hidden, paused, reduced-motion, entry and method-view states reset and stop the response. The previous foil renderer is retained in source for reversibility but does not mount on the current hero.

The former identity card's DESIGN, BUILD, TEST, REFINE, SHIP content lives in an optional How I build disclosure in the portrait area. Double-clicking the portrait opens it; a visible native control provides the same action for keyboard and touch and returns to the portrait. The content is hidden by default and does not introduce a new card or modal. Explore the work is the hero's primary navigation action; About remains in the main navigation.

The owner removed the two PBR assembly plates and the RANGraph fixture preview panel from the lower home. These renderers no longer mount there. Their essential project content and destinations remain; detailed diagrams and simulations are available in the project instruments. Instrument frames retain dark glass gradients, subdued borders, inset edges and ambient depth; supporting work uses separators.

### Inputs / Fields

RANGraph's entity inspector uses a native dark select with warm text and visible focus; mobile input type is (16px). Hardware inputs remain buttons with pressed state, labels and switch indicators. Cyan and fault red express the actual simulated state.

### System Dock and Stage Controls

The former three-system dock is removed at the owner’s request. The hero action is Explore the work and links to the systems section. Project actions and stage inspection remain below the hero and in direct project instruments.

### Reference Fields and Renderer Lifecycle

Flow Field, Matrix Field, Constellation Field and Gateway Flow ship as actual MIT ThreeUI Community 1.2.0 renderer frames. The effect scripts are retained; unused remote page services are removed and the original GSAP runtime is served locally. They are decorative, inert and hidden from assistive technology.

Frames mount only while their host is visible, the tab is active, motion is allowed and the host is enabled. The home-wide Pause/Resume state applies to the hero, project features and research fields, including later mounts. Pausing, hiding, going offscreen or reduced motion unmounts the affected frame; speed zero is not a reliable upstream pause. The hero field can warm up behind the intro. The Ignition render loop stops hidden/offscreen, tracks preference changes and cleans up resources.

### Optional Entry

The face exists only in the deliberate Scan entry. A full home refresh resets the gate like V1; same-document navigation keeps completion. The supplied mesh waits visibly for Scan, then traces upward/downward, dissolves and disposes before the identity card mounts. The active scan is (6.2 seconds). Load and running-sequence failure deadlines provide an alternate entry, rather than trap visitors. Compact screens, reduced motion and failures expose Skip/Enter. Standby does not continuously render idle frames. No camera access, random confidence or inference timing is presented.

The illustrative Lee Perry-Smith head is not Vishva's portrait. The sequence labels its no-camera/no-model-inference status. The sole shipping raster's sourced origin is recorded in docs/DESIGN-IMPLEMENTATION.md.

## Do's and Don'ts

### Do:

- **Do** retain the actual reference fields, warm HTML identity and gold/cyan foil relationship.
- **Do** distinguish decorative atmosphere from source-backed project data.
- **Do** retain native actions, visible focus, bounded keyboard inspection and mobile vertical scrolling.
- **Do** use source-backed project overviews and retain home-wide Pause/Resume with the standalone portrait.
- **Do** unmount decorative frames when paused, hidden, offscreen or reduced motion is requested.
- **Do** keep exact upstream attribution and custom-study boundaries adjacent to the design record.

### Don't:

- **Don't** replace the pinned reference materials with the rejected optical-workbench translation.
- **Don't** call the custom card Ashen One source or the face a Cortexa Pro component.
- **Don't** claim a zero-speed control reliably pauses every upstream renderer.
- **Don't** invent telemetry, benchmarks, publications or wireless relationships.
- **Don't** present schematic geometry as a measured hardware prototype or running model inference.
- **Don't** leave the temporary face in the persistent home composition.
